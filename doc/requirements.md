# 採点AI学習アプリ 要件定義

- 作成日: 2026-09-11
- ステータス: 確定(実装着手前)
- スタック: Laravel + Blade(Livewire不使用)
- 採点: Claude API

## 1. 概要・目的

自由記述で解答した問題を AI(Claude API)が採点し、フィードバックを返す**完全個人用**の学習アプリ。
問題の作成・解答・履歴確認まで、すべて自分ひとりで使うことを前提とする。他ユーザーとの共有・公開機能は持たない。

**今回のアプリの位置づけ**: 今回作るものはプロトタイプであり、デプロイは行わない(ローカル環境での動作確認まで)。ポートフォリオとして提出するのは、今回の検証を踏まえて後日改めて作り直すバージョンで、そちらは本番デプロイまで行う想定。

## 2. 対象ユーザー

- 管理者(自分)1名のみ。
- 一般ユーザー登録機能は設けない。ログインできる = 管理者、という前提。

## 3. 機能要件

### 3.1 認証・アカウント

| 機能 | 内容 | 優先度 |
|---|---|---|
| ログイン | 管理者アカウントでログイン | 必須 |
| ログアウト | セッション終了 | 必須 |
| 会員登録 | **なし**。登録画面・ルートは作らない | - |
| 管理者アカウント投入 | Seeder で admin ユーザー(email/password)を1件投入 | 必須 |

> ユーザーは実質1人のみのため、`role` や `is_admin` カラムは不要。ログイン可能な唯一のユーザー = 管理者として扱う。

### 3.2 問題管理

| 機能 | 内容 | 優先度 |
|---|---|---|
| 問題作成 | タイトル・問題文を入力して登録 | 必須 |
| 編集・削除 | 自分の問題を編集・削除 | 必須 |
| 問題一覧 | 自分が登録した問題の一覧・検索 | 必須 |
| カテゴリ分類 | 問題を親子2階層のカテゴリで分類・絞り込み | 必須 |
| カテゴリ管理 | 親カテゴリ・子カテゴリの作成・編集・削除 | 必須 |

> 公開/非公開の概念は不要(他ユーザーがいないため削除)。

**カテゴリ仕様(確定)**:
- 階層は **親カテゴリ → 子カテゴリ** の2階層まで(それ以上のネストはしない)
- 1問題につき、カテゴリは **1つだけ**紐づける(タグのような複数付与はしない)
- 問題には親カテゴリを直接ではなく、子カテゴリ(または親カテゴリ単体)を割り当てる想定

### 3.3 回答・AI採点

| 機能 | 内容 | 優先度 |
|---|---|---|
| 問題選択 | 問題一覧からチェックボックスで **1〜10問** を選んで回答セッションを開始 | 必須 |
| 採点レベル選択 | セッション開始時に **優しい / 普通 / 厳しい** の3段階から採点の厳しさを選ぶ | 必須 |
| 一括回答フォーム | 選択した問題をまとめて表示し、それぞれに自由記述で解答を入力 | 必須 |
| AI一括採点実行 | 選択した全問題(問題文+回答)+採点レベルを **1回の Claude API リクエスト** にまとめて送信し採点 | 必須 |
| 採点結果表示 | 問題ごとの点数(0〜100点)+評価コメントを一覧表示 | 必須 |
| 採点結果保存 | 問題ごとに回答・点数・コメントをDBへ保存(保存単位は問題ごと、APIリクエストは1回) | 必須 |
| 再挑戦 | 同じ問題に何度でも再解答・再採点できる | 必須 |

**一括採点の仕様(確定)**:
- 1リクエストあたりの問題数は **最低1問・最大10問**。10問を超える選択はバリデーションでエラーにする。
- Claude API へのリクエストは、選択した問題文+ユーザーの解答+採点レベルをまとめて1回送信し、レスポンスは「問題ごとのscore/feedbackの配列」構造(JSON)で受け取る。
- レスポンスを問題単位に分解し、`answers` / `scores` にはこれまで通り問題ごとに1レコードずつ保存する(テーブル構造の変更は不要)。

**採点レベルの仕様(確定)**:
- 3段階: **優しい / 普通 / 厳しい**。回答セッション開始時(問題選択と同じ画面)で毎回選択する。
- レベルごとにプロンプト内の採点方針(加点寄り/標準/減点寄り、どこまで厳密に正確性を求めるか等)を明示的に変え、AIへの指示を固定化することで採点のブレを抑える。
- 選択したレベルは `answers`(または `scores`)にどのレベルで採点したかを記録し、履歴画面でも確認できるようにする。

**採点方式(合意事項)**: 模範解答・採点基準の事前登録は行わない。AIが問題文と回答のみから自己判断で妥当な採点を行う。将来的にルーブリックや模範解答の任意入力を追加できるよう、DB設計上は拡張余地を残す。

**採点仕様(確定)**:
- 点数は **100点満点**(0〜100の整数)
- 評価コメントは **日本語**で返す

### 3.4 履歴・成績管理

| 機能 | 内容 | 優先度 |
|---|---|---|
| 回答履歴一覧 | 解答した問題・点数・日時の一覧 | 必須 |
| 得点推移 | 日時ごとの点数推移をグラフ表示 | 必須 |
| 履歴の絞り込み | 期間・問題単位でのフィルタ | 任意 |
| 履歴の自動整理 | 同一問題については直近10件のみ保持し、それより古い履歴は自動削除 | 必須 |

## 4. 非機能要件

- **技術スタック**: Laravel + Blade のみ。Livewire は使用しない。必要な動的UIは通常のフォーム送信 or 素のJS/Alpine.js程度に留める。
- **DB**: MySQL または SQLite(開発初期はSQLiteで可)。
- **AI連携**: Anthropic Claude API(Messages API)をサーバーサイドから呼び出し。APIキーは `.env` で管理し、リポジトリに含めない。
- **処理方式**: MVPでは採点をリクエスト同期で実行。レイテンシが問題になる場合はQueueによる非同期化を後続検討。
- **コスト・乱用対策**: 個人利用のみのため、API呼び出し回数の上限は設けない。
- **認可**: 全画面ログイン必須(認証ミドルウェア)。ログイン画面以外は未認証アクセス不可。
- **入力対策**: フォーム入力値のバリデーション、XSS対策(Bladeエスケープ徹底)。

## 5. 画面一覧

| 画面 | 概要 |
|---|---|
| `/`(ルート) | `/login` へリダイレクト。アプリの起点はログイン画面 |
| `/login` | 管理者ログイン(登録画面なし) |
| `/questions` | 自分の問題一覧(検索・絞り込み) |
| `/questions/create` | 問題作成フォーム(親子カテゴリを選択) |
| `/categories` | カテゴリ(親・子)の一覧・作成・編集・削除 |
| `/questions/{id}` | 問題詳細プレビュー |
| `/answers/create?ids=...` | 選択した1〜10問への一括回答フォーム(採点レベルも選択) |
| `/answers/result?batch=...` | 一括採点結果(問題ごとの点数・コメント)一覧表示 |
| `/history` | 回答履歴・得点推移 |

## 6. データモデル(概略)

```
users            (admin 1件のみ / Seederで投入)
  id (PK)
  name
  email
  password

categories
  id (PK)
  parent_id (FK -> categories.id, nullable)  ※nullなら親カテゴリ、値があれば子カテゴリ
  name

questions
  id (PK)
  user_id (FK -> users.id)   ※将来のマルチユーザー拡張余地として残す
  category_id (FK -> categories.id, nullable)
  title
  body
  created_at

answers
  id (PK)
  question_id (FK -> questions.id)
  user_id (FK -> users.id)
  body
  created_at

scores
  id (PK)
  answer_id (FK -> answers.id)  ※1:1
  score
  feedback
  grading_level (easy / normal / hard)
```

`scores` は `answers` に1:1で紐づく想定(実装簡略化のため `answers` テーブルへのカラム統合も選択肢)。

## 7. スコープ外(将来検討)

- 本番デプロイ・本番運用相当の対応(独自ドメイン、HTTPS、監視、バックアップ等)— 今回はプロトタイプのためローカル動作確認までとし、作り直す際に対応
- 複数ユーザー対応・ユーザー登録機能
- 選択式問題、音声・画像による解答への対応
- 模範解答・ルーブリック(複数観点評価)の任意登録機能
- 採点処理のQueueによる非同期化・キャッシュ
- タグ検索・レコメンドの高度化

## 8. 決定事項サマリー

| 論点 | 決定内容 |
|---|---|
| 点数のスケール | 100点満点(0〜100の整数) |
| 採点コメントの言語 | 日本語固定 |
| 公開問題(他ユーザー共有) | なし(完全個人用のため対象外) |
| API呼び出し回数の上限 | 設けない |
| 同じ問題への再挑戦 | 可能。再挑戦のたびに再採点する |
| 履歴の保持件数 | 同一問題につき直近10件のみ保持し、古いものは自動削除 |
| 管理者アカウントの投入方法 | Seeder に email / password を直接記述する(プロトタイプの個人用途のため `.env` 分離はせず、固定値でシンプルに) |
| カテゴリ階層 | 親カテゴリ→子カテゴリの2階層まで、1問題1カテゴリ |

未確定事項はすべて解消。要件定義はこれで確定とする。
