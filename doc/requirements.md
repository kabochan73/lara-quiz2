# 採点AI学習アプリ 要件定義

- 作成日: 2026-09-11
- 更新日: 2026-09-12(カテゴリ起点のページ構成に再設計)
- ステータス: 確定
- スタック: Laravel + Blade(Livewire不使用)
- 採点: Claude API

## 1. 概要・目的

自由記述で解答した問題を AI(Claude API)が採点し、フィードバックを返す**完全個人用**の学習アプリ。
問題の作成・解答・履歴確認まで、すべて自分ひとりで使うことを前提とする。他ユーザーとの共有・公開機能は持たない。

**今回のアプリの位置づけ**: 今回作るものはプロトタイプであり、デプロイは行わない(ローカル環境での動作確認まで)。ポートフォリオとして提出するのは、今回の検証を踏まえて後日改めて作り直すバージョンで、そちらは本番デプロイまで行う想定。

## 2. 対象ユーザー

- 管理者(自分)1名のみ。
- 一般ユーザー登録機能は設けない。ログインできる = 管理者、という前提。

## 3. 機能要件

### 3.1 認証・アカウント

| 機能 | 内容 | 優先度 |
|---|---|---|
| ログイン | 管理者アカウントでログイン | 必須 |
| ログアウト | セッション終了 | 必須 |
| 会員登録 | **なし**。登録画面・ルートは作らない | - |
| 管理者アカウント投入 | Seeder で admin ユーザー(email/password)を1件投入 | 必須 |

> ユーザーは実質1人のみのため、`role` や `is_admin` カラムは不要。ログイン可能な唯一のユーザー = 管理者として扱う。

### 3.2 カテゴリ・問題管理

**ページ構成の方針(確定・2026-09-12改訂)**: 当初は「問題一覧」を独立した画面として持ち、カテゴリは分類・絞り込みのための付属機能という位置づけだったが、実際に使ってみると自由度が高すぎて散らかったため、**カテゴリを起点に問題を作る・見る**構成に再設計した。全体横断の問題一覧・キーワード検索は廃止する。

| 機能 | 内容 | 優先度 |
|---|---|---|
| カテゴリ一覧 | 親カテゴリの一覧(トップ画面)。右上に「+ 新規カテゴリ作成」 | 必須 |
| カテゴリ作成 | 親カテゴリを作成するフォーム(独立ページ) | 必須 |
| カテゴリ詳細 | 1つのカテゴリの中身を見るページ。親カテゴリなら子カテゴリ一覧+「+ 子カテゴリを追加」、子カテゴリなら問題一覧+「+ 問題を追加」を表示 | 必須 |
| カテゴリ編集・削除 | カテゴリ名・親カテゴリの変更、削除 | 必須 |
| 問題作成 | カテゴリ詳細ページの「+ 問題を追加」から遷移。問題文のみ入力(カテゴリは選択済み、タイトルは持たない) | 必須 |
| 問題編集・削除 | 自分の問題を編集・削除 | 必須 |
| 問題詳細プレビュー | 1問の内容を確認する画面 | 必須 |

**カテゴリ仕様(確定)**:
- 階層は **親カテゴリ → 子カテゴリ** の2階層まで(それ以上のネストはしない)
- 1問題につき、カテゴリは **1つだけ**紐づけ、**必須**(未分類は廃止)
- 問題は親カテゴリ・子カテゴリのどちらに対しても直接紐づけられる(子カテゴリを作らず親カテゴリ直下に問題を置いてもよい)
- **1カテゴリにつき問題は最大10問まで**(確定・2026-09-12改訂)。回答は常にカテゴリ内の全問一括で行う方式にしたため、その前提を問題作成の時点で守らせる。11問目の作成・他カテゴリからの移動は拒否する。
- **カテゴリを削除すると、そのカテゴリに属する問題・回答履歴・採点結果もすべて連動して削除される**(親カテゴリを削除した場合は子カテゴリごと削除)。DBの外部キーのcascade削除で担保する。

### 3.3 回答・AI採点

**方針(確定・2026-09-12改訂)**: 問題を選んで回答する方式(チェックボックスで1〜10問選択)をやめ、**カテゴリ内の全問題に常に一括で回答する**シンプルな方式にした。1カテゴリ最大10問という制限があるため、これでも一括採点のAPI上限(最大10問)と矛盾しない。

| 機能 | 内容 | 優先度 |
|---|---|---|
| 回答セッション開始 | カテゴリ詳細ページの「全問(N問)に回答する」から、そのカテゴリの全問題への回答セッションを開始 | 必須 |
| 採点レベル選択 | セッション開始時に **優しい / 普通 / 厳しい** の3段階から採点の厳しさを選ぶ | 必須 |
| 一括回答フォーム | カテゴリ内の全問題をまとめて表示し、それぞれに自由記述で解答を入力 | 必須 |
| AI一括採点実行 | 全問題(問題文+回答)+採点レベルを **1回の Claude API リクエスト** にまとめて送信し採点 | 必須 |
| 採点結果表示 | 問題ごとの点数(0〜100点)+評価コメントを一覧表示 | 必須 |
| 採点結果保存 | 問題ごとに回答・点数・コメントをDBへ保存(保存単位は問題ごと、APIリクエストは1回) | 必須 |
| 再挑戦 | 同じ問題に何度でも再解答・再採点できる | 必須 |

**一括採点の仕様(確定)**:
- 1カテゴリ最大10問という制限があるため、1リクエストあたりの問題数は自然に **最大10問** に収まる。
- Claude API へのリクエストは、全問題の問題文+ユーザーの解答+採点レベルをまとめて1回送信し、レスポンスは「問題ごとのscore/feedbackの配列」構造(JSON)で受け取る。
- 「カテゴリ内の全問に一括回答した1回分」は `attempts` テーブルの1レコード(Attempt)としてまとめ、`answers` は各問題ごとに1レコードずつAttemptにぶら下がる形で保存する(2026-09-12改訂)。

**採点レベルの仕様(確定)**:
- 3段階: **優しい / 普通 / 厳しい**。回答セッション開始時に毎回選択する。
- レベルごとにプロンプト内の採点方針(加点寄り/標準/減点寄り、どこまで厳密に正確性を求めるか等)を明示的に変え、AIへの指示を固定化することで採点のブレを抑える。
- 採点レベルは回答単位ではなく **挑戦(Attempt)単位** で1つ記録する(同じ挑戦内の全問に共通のレベルが適用されるため)。

**採点方式(合意事項)**: 模範解答・採点基準の事前登録は行わない。AIが問題文と回答のみから自己判断で妥当な採点を行う。将来的にルーブリックや模範解答の任意入力を追加できるよう、DB設計上は拡張余地を残す。

**採点仕様(確定)**:
- 点数は **100点満点**(0〜100の整数)
- 評価コメントは **日本語**で返す

### 3.4 履歴・成績管理

**方針(確定・2026-09-12改訂、Udemy風に再改訂)**: 履歴は問題単位ではなく、**「カテゴリの全問に一括回答した1回分(挑戦/Attempt)」を単位**にまとめる。Udemyのクイズ結果のように、履歴一覧は挑戦ごとの日時・問題数・平均点を並べ、1件を開くとその挑戦で答えた全問題の問題文・回答・点数・フィードバックをまとめて確認できる。グラフ・期間絞り込みは使わないと判断し廃止。

| 機能 | 内容 | 優先度 |
|---|---|---|
| カテゴリ別履歴一覧 | そのカテゴリで行った挑戦(Attempt)を新しい順に一覧表示(日時・問題数・採点レベル・平均点)。カテゴリ詳細ページの「履歴を見る」から遷移 | 必須 |
| 履歴詳細 | 履歴一覧の1件(1回分の挑戦)をクリックすると、その回で答えた全問題の問題文・回答全文・点数・フィードバック全文をまとめて表示(採点直後の結果画面と同じ内容) | 必須 |
| 履歴の自動整理 | 同一問題については回答(answers)を直近10件のみ保持し、それより古いものは自動削除。この結果、回答が0件になった挑戦(Attempt)も自動的に削除される | 必須 |

## 4. 非機能要件

- **技術スタック**: Laravel + Blade のみ。Livewire は使用しない。必要な動的UIは通常のフォーム送信 or 素のJS/Alpine.js程度に留める。
- **実行環境**: Docker(自作 docker-compose)。app(PHP-FPM) + nginx + postgres の構成。Laravel Sail は使わない。
- **DB**: PostgreSQL。
- **AI連携**: Anthropic Claude API(Messages API)をサーバーサイドから呼び出し。APIキーは `.env` で管理し、リポジトリに含めない。
- **処理方式**: MVPでは採点をリクエスト同期で実行。レイテンシが問題になる場合はQueueによる非同期化を後続検討。
- **コスト・乱用対策**: 個人利用のみのため、API呼び出し回数の上限は設けない。
- **認可**: 全画面ログイン必須(認証ミドルウェア)。ログイン画面以外は未認証アクセス不可。
- **入力対策**: フォーム入力値のバリデーション、XSS対策(Bladeエスケープ徹底)。

## 5. 画面一覧

| 画面 | 概要 |
|---|---|
| `/`(ルート) | `/login` へリダイレクト。アプリの起点はログイン画面 |
| `/login` | 管理者ログイン(登録画面なし) |
| `/categories` | ログイン後の着地点。親カテゴリ一覧 + 「+ 新規カテゴリ作成」 |
| `/categories/create` | カテゴリ作成フォーム |
| `/categories/{category}` | カテゴリ詳細。親なら子カテゴリ一覧+追加、子なら問題一覧+追加、どちらも「履歴を見る」への導線あり |
| `/categories/{category}/edit` | カテゴリ編集 |
| `/categories/{category}/questions/create` | 問題作成フォーム(カテゴリはURLで固定、選択不要) |
| `/questions/{id}` | 問題詳細プレビュー |
| `/questions/{id}/edit` | 問題編集(カテゴリの変更は可能) |
| `/categories/{category}/answers/create` | そのカテゴリの全問題(最大10問)への一括回答フォーム(採点レベルも選択) |
| `/categories/{category}/answers` (POST結果) | 一括採点結果(問題ごとの点数・コメント)一覧表示 |
| `/categories/{category}/history` | そのカテゴリでの挑戦(Attempt)一覧(日時・問題数・平均点) |
| `/categories/{category}/history/{attempt}` | 挑戦1回分の詳細(その回の全問題の問題文・回答・点数・フィードバック) |

## 6. データモデル(概略)

```
users            (admin 1件のみ / Seederで投入)
  id (PK)
  name
  email
  password

categories
  id (PK)
  parent_id (FK -> categories.id, nullable)  ※nullなら親カテゴリ、値があれば子カテゴリ
  name

questions
  id (PK)
  user_id (FK -> users.id)   ※将来のマルチユーザー拡張余地として残す
  category_id (FK -> categories.id, NOT NULL, カテゴリ削除時はcascade)
  body
  created_at

attempts        ※カテゴリの全問に一括回答した「1回分」(Udemyのクイズ結果の1回に相当)
  id (PK)
  category_id (FK -> categories.id, カテゴリ削除時はcascade)
  user_id (FK -> users.id)
  grading_level (easy / normal / hard)  ※この挑戦全体に適用したレベル
  created_at

answers
  id (PK)
  question_id (FK -> questions.id)
  user_id (FK -> users.id)
  attempt_id (FK -> attempts.id, 挑戦削除時はcascade)
  body
  created_at

scores
  id (PK)
  answer_id (FK -> answers.id)  ※1:1
  score
  feedback
```

`scores` は `answers` に1:1で紐づく想定(実装簡略化のため `answers` テーブルへのカラム統合も選択肢)。

## 7. スコープ外(将来検討・対象外)

- 本番デプロイ・本番運用相当の対応(独自ドメイン、HTTPS、監視、バックアップ等)— 今回はプロトタイプのためローカル動作確認までとし、作り直す際に対応
- 複数ユーザー対応・ユーザー登録機能
- 選択式問題、音声・画像による解答への対応
- 模範解答・ルーブリック(複数観点評価)の任意登録機能
- 採点処理のQueueによる非同期化・キャッシュ
- カテゴリをまたいだ一括回答・全体横断の問題一覧やキーワード検索(カテゴリ起点の構成に一本化したため廃止)
- 未分類(カテゴリなし)の問題(廃止、category_idは必須)
- 得点推移のグラフ表示、履歴の期間絞り込み(廃止、カテゴリ単位の一覧+詳細のみ)

## 8. 決定事項サマリー

| 論点 | 決定内容 |
|---|---|
| 点数のスケール | 100点満点(0〜100の整数) |
| 採点コメントの言語 | 日本語固定 |
| 公開問題(他ユーザー共有) | なし(完全個人用のため対象外) |
| API呼び出し回数の上限 | 設けない |
| 同じ問題への再挑戦 | 可能。再挑戦のたびに再採点する |
| 履歴の保持件数 | 同一問題につき直近10件のみ保持し、古いものは自動削除 |
| 管理者アカウントの投入方法 | Seeder に email / password を直接記述する(プロトタイプの個人用途のため `.env` 分離はせず、固定値でシンプルに) |
| カテゴリ階層 | 親カテゴリ→子カテゴリの2階層まで、1問題1カテゴリ(必須) |
| ページ構成 | カテゴリ一覧→カテゴリ詳細(子カテゴリ or 問題+追加ボタン)→問題、の階層構造に一本化(2026-09-12) |
| カテゴリをまたいだ回答 | しない。回答は常に同一カテゴリ内の問題だけで完結する |
| カテゴリ削除時の挙動 | 配下の問題・回答履歴・採点結果もすべて連動削除(cascade) |
| 履歴の見せ方 | Udemy風に「挑戦(Attempt)単位」の一覧+詳細(2026-09-12再改訂)。問題ごとではなく、カテゴリ全問への1回の回答をまとめて表示。グラフ・期間絞り込みは廃止 |
| 1カテゴリの問題数上限 | 最大10問(2026-09-12改訂)。問題選択式をやめ、カテゴリ全問一括回答に変更したため |
| 回答方式 | 問題を選ばず、カテゴリ内の全問に常に一括回答する(2026-09-12改訂) |

未確定事項はすべて解消。要件定義はこれで確定とする。
